# QuantLens-XAI: Security and Risk Analysis Review

## 1. Zero Cloud Data Leakage (Local Air-Gapped Operation)
QuantLens-XAI is architected with a strict privacy boundary:
- **Local LLM**: Strategy prompts are parsed exclusively via local Ollama daemon on `127.0.0.1:11434`. No prompt tokens or strategy logic are ever sent to external cloud APIs (e.g. OpenAI, Anthropic).
- **Local Databases**: SQLite database resides at `instance/local.db` and MongoDB listens exclusively on `127.0.0.1:27017` (loopback only, closed to WAN/LAN).

---

## 2. Real-Money Protection & Paper Trading Isolation
- **Mode Isolation**: Paper trading mode is strictly decoupled from live broker execution. Live order dispatch pathways require explicit administrative activation and API key decryption.
- **Double-Entry Ledger Protection**: In `quantlens/paper_broker.py`, any attempt to purchase shares exceeding `available_cash` raises an immediate `ValueError("Insufficient available capital")`. Negative cash balances are mathematically impossible.
- **Idempotency**: All order submissions require unique or autogenerated idempotency tokens, preventing double-submission attacks.

---

## 3. Input Validation and Defense in Depth
- **Pydantic v2 Type Enforcement**: All incoming strategy payloads must pass strict validation before execution.
- **SQL Injection Prevention**: SQLAlchemy parameterized queries and ORM mappings completely eliminate raw string interpolation.
- **NoSQL Injection Prevention**: MongoDB queries utilize typed dictionaries with parameterized key lookups (`{"symbol": symbol}`), preventing BSON injection.
